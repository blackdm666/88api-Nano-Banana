# 更新说明 v1.3.4

## Pro 长任务连接

- 实测确认非流式 Pro 请求可在 88API 后台成功并计费，但旧客户端可能在约 45 秒提前 `fetch failed`；请求实际响应时间可超过 1 分钟。
- 改用原始 HTTPS/1.1 请求，显式使用 `Accept-Encoding: identity`，绕开高层 `fetch` 的响应解码路径，并保留 10 分钟超时。
- 等待期间每 15 秒输出一次本地心跳，避免长时间无输出。
- 实测该 Gemini 图片渠道对 `stream: true` 返回 HTTP 500，因此不启用 Chat Completions SSE。

## 失败后重新提交

- 将容易被理解为永久禁令的 `[NO-RETRY]` 改为 `[NO-AUTO-RETRY]`。
- 已受理或状态未知的请求仍不会被插件自动重发、切换模型或回退，避免重复计费。
- 用户在看到风险提示后明确说“重试”“重新生成”“再试一次”时，视为授权一次新的付费请求；Codex 不再强制用户先查看 88API 日志。
- 兼容旧版本输出的 `[NO-RETRY]`，同样只禁止自动重试，不阻止用户明确发起新请求。
